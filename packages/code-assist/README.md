# @tearleads/code-assist

Self-hosted AI pull-request reviewer, replacing the Gemini Code Assist GitHub app
(the consumer `gemini-code-assist[bot]` stops reviewing on **2026-07-17**).

Delivery model: a **GitHub App + webhook server** (Bun) running on our Hetzner
infra behind the existing Cloudflare tunnel. Reviews are generated by **DeepSeek
V4** (BYOK) through its OpenAI-compatible API, kept behind a single client
factory so the provider is swappable.

## Status

- **Phase 1 — review core + CLI (done).** Generate and (optionally) post a review
  for any PR from the command line, authenticating with a local token.
- **Phase 2 — webhook server (done).** `Bun.serve` + `X-Hub-Signature-256`
  verification + GitHub App installation-token auth; auto-review on `pull_request`
  opened/reopened.
- **Phase 3 — interactive re-check (done).** A mention of the bot on a review
  thread re-checks that finding against the current code and replies; auto-review
  also runs on `synchronize`, de-duplicated so a push only surfaces new findings.
- **Phase 4 — deploy (done).** Compiled Bun executable run by systemd behind the
  Cloudflare tunnel; provisioned by Ansible + Terraform, gated on
  `CODE_ASSIST_ENABLED` so existing deploys are unaffected until opted in.

## CLI usage (Phase 1)

```sh
# Dry run — prints the findings it WOULD post, nothing is published.
DEEPSEEK_API_KEY=sk-... bun run --cwd packages/code-assist review 1056

# Publish the review to the PR.
DEEPSEEK_API_KEY=sk-... bun run --cwd packages/code-assist review 1056 --post

# Review a PR in another repo.
DEEPSEEK_API_KEY=sk-... bun run --cwd packages/code-assist review 42 --repo=owner/name
```

GitHub auth resolves from `GITHUB_TOKEN`/`GH_TOKEN`, falling back to the local
`gh auth token`. The review is posted as a `COMMENT` event, so it never blocks a
merge.

## Webhook server (Phase 2)

```sh
bun run --cwd packages/code-assist dev    # hot-reload
bun run --cwd packages/code-assist start  # production
```

Routes: `POST /webhook` (GitHub events) and `GET /health`. Every delivery is
verified against `X-Hub-Signature-256`; the review then runs detached so GitHub
gets a fast `202`. Requires the App env vars below in addition to the review
config.

## Configuration

Review config (shared by CLI and server):

| Env var | Default | Purpose |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | _(required)_ | DeepSeek API key (BYOK). |
| `CODE_ASSIST_MODEL` | `deepseek-v4-flash` | Model id. Use `deepseek-v4-pro` for higher-quality reviews. Do **not** use the legacy `deepseek-chat`/`deepseek-reasoner` ids — retired 2026-07-24. |
| `CODE_ASSIST_BASE_URL` | `https://api.deepseek.com` | OpenAI-compatible base URL; point elsewhere to swap providers. |
| `CODE_ASSIST_SEVERITY_THRESHOLD` | `medium` | Minimum severity to post (`low`/`medium`/`high`/`critical`). |
| `CODE_ASSIST_MAX_COMMENTS` | `25` | Cap on inline comments per review (highest severity first). |
| `CODE_ASSIST_BOT_HANDLE` | `@tearleads-code-assist` | Mention string that triggers an interactive re-check on a review thread. |
| `CODE_ASSIST_IGNORE_PATTERNS` | lockfiles + build output | Comma-separated globs of paths to skip reviewing (replaces the default list). |

Server-only config:

| Env var | Default | Purpose |
| --- | --- | --- |
| `CODE_ASSIST_GITHUB_APP_ID` | _(required)_ | Numeric GitHub App ID. |
| `CODE_ASSIST_GITHUB_PRIVATE_KEY_PATH` | _(one of these)_ | Path to the App's PEM private key. |
| `CODE_ASSIST_GITHUB_PRIVATE_KEY` | _(one of these)_ | The PEM inline (escaped `\n` allowed). |
| `CODE_ASSIST_GITHUB_WEBHOOK_SECRET` | _(required)_ | Webhook secret for signature verification. |
| `CODE_ASSIST_HOST` | `127.0.0.1` | Bind address for `Bun.serve` (loopback; the tunnel reaches it locally). |
| `CODE_ASSIST_PORT` | `3939` | Port for `Bun.serve`. |

## Registering the GitHub App

One-time manual setup (Settings → Developer settings → GitHub Apps → New):

1. **Name:** `tearleads-code-assist`. **Homepage:** the repo URL.
2. **Webhook → Active.** URL = the tier's API hostname +
   `/code-assist/webhook` (for example,
   `https://api.tearleads.com/code-assist/webhook`). Set a **Webhook secret**
   and put the same value in `CODE_ASSIST_GITHUB_WEBHOOK_SECRET`.
3. **Repository permissions:** Pull requests = **Read & write**;
   Contents = **Read-only**; Metadata = **Read-only**.
4. **Subscribe to events:** `Pull request` and `Pull request review comment`.
5. **Where can this be installed:** Only on this account.
6. Create the app, then **Generate a private key** (downloads a `.pem`) and note
   the numeric **App ID**.
7. **Install** the app on `a2f0/tearleads`.
8. Set `CODE_ASSIST_GITHUB_APP_ID` and point
   `CODE_ASSIST_GITHUB_PRIVATE_KEY_PATH` at the `.pem`, then run the server.

The App reads the installation id from each webhook payload, so it is not
configured manually.

## Deployment (Phase 4)

The bot deploys to the Hetzner server alongside the API: a compiled Bun
executable (`bun run build` → `dist/tearleads-code-assist`) run by systemd,
listening on `127.0.0.1:3939`, reached only through the Cloudflare tunnel (the
host firewall allows just 22/80/443 inbound). All provisioning is gated on
`CODE_ASSIST_ENABLED=true`.

One-time setup:

1. Register the GitHub App (above). Save its private key to
   `.secrets/code-assist-app.pem`; note the App ID and webhook secret.
2. Add the bot secrets to `.secrets/prod.env` (and/or `.secrets/staging.env`):

   ```sh
   CODE_ASSIST_ENABLED=true
   DEEPSEEK_API_KEY=sk-...
   CODE_ASSIST_GITHUB_APP_ID=123456
   CODE_ASSIST_GITHUB_WEBHOOK_SECRET=...
   CODE_ASSIST_GITHUB_PRIVATE_KEY_SRC=/absolute/path/to/.secrets/code-assist-app.pem
   ```

3. `terraform/stacks/prod/server/scripts/apply.sh` — provisions the shared API
   hostname and tunnel route.
4. `ansible/scripts/run-server-prod.sh` — installs the env file, private key,
   `tearleads-code-assist` systemd unit, and API-host path proxy.
5. `packages/code-assist/scripts/deployProductionCodeAssist.sh` — builds, ships,
   and starts the executable.
6. Point the GitHub App webhook URL at
   `https://api.tearleads.com/code-assist/webhook` for production or
   `https://api-staging.tearleads.com/code-assist/webhook` for staging.

Redeploying new bot code afterward is just step 5. Staging uses the `staging` /
`*Staging*` variants of each command.

## How a review is produced

1. Fetch the PR's changed files (`pulls.listFiles`) and rebuild a unified diff.
2. Parse each file's patch to learn which new-side line numbers are valid comment
   anchors (the reviews API rejects out-of-diff lines with 422).
3. Ask DeepSeek for findings via a forced `submit_review` tool call (structured
   output: `path`, `line`, `severity`, `title`, `body`, optional `suggestion`).
4. Drop findings below the severity threshold or whose anchor is not in the diff,
   cap to the max, and post one review with all inline comments.
