# Subsystems

A **subsystem** is a stable proper noun for a slice of the system that a
developer reasons about as one unit, such as "Containers" or "Realtime Sync".
Conversation, PR descriptions, and code review use it to say _where a feature
lives_ and _who owns it_.

A subsystem is an ownership and navigation index over existing paths. Import
direction stays enforced by the lanes, layers, and
[planes](./api-architecture.md#protocol-planes) in
[`dependency-cruiser.config.ts`](../dependency-cruiser.config.ts). A subsystem
may span layers: `Containers` covers its routes, service facade, and
orchestration workflows. A subsystem that declares a **surface** is also a
boundary: other subsystems import only its surface files. See the
[architecture vocabulary](developer/architecture-vocabulary.md) for the related
axes.

## How it is kept honest

- [`scripts/architecture/subsystems.ts`](../scripts/architecture/subsystems.ts)
  is the machine-readable manifest: each subsystem lists the path prefixes and
  exact files it owns. The client SDK's rows live in
  [`scripts/architecture/clientSdkSubsystems.ts`](../scripts/architecture/clientSdkSubsystems.ts).
- The `subsystem-registry-covers-every-source-file` architecture check requires
  every production source file in a registered package to map to **exactly one**
  subsystem, so a new file with no home fails `bun run lint:architecture`
  instead of silently becoming an orphan.
- The `subsystem-registry-matches-docs` check keeps the table below in lockstep
  with the manifest.
- `subsystem-imports-use-declared-surface` enforces surfaces; see
  [SDK seams](developer/client-sdk-seams.md#subsystem-surfaces).

Registered packages: [`packages/api`](../packages/api/),
[`packages/client-sdk`](../packages/client-sdk/), and
[`packages/app`](../packages/app/).

## Adding or changing a subsystem

1. Edit
   [`scripts/architecture/subsystems.ts`](../scripts/architecture/subsystems.ts)
   (or
   [`clientSdkSubsystems.ts`](../scripts/architecture/clientSdkSubsystems.ts)
   for the client SDK) so the owning subsystem's `paths` claim the new file, or
   add a new subsystem entry.
2. Mirror the change in the table above.
3. Run `bun run lint:architecture`. The coverage check reports any file that
   maps to zero or several subsystems; the docs check reports table/manifest
   drift.
